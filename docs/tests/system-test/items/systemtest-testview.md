# システム試験（ST）試験観点書

以下は、要件定義書、機能一覧、画面設計、処理設計、API カタログ、IF 設計、DB 設計、ER 図に記載された内容のみを根拠として整理したシステム試験観点である。

| No | 大分類 | 小分類 | テスト観点 | 説明 |
|----|--------|--------|------------|------|
| 1 | 機能性 | 認証処理の成立性 | 正常な認証情報でログインできること | 組合員コードとパスワードが正しい場合に認証が成功し、セッション作成後にトップ画面へ遷移することを確認する。 |
| 2 | 機能性 | 認証エラー制御 | 誤った認証情報でログイン拒否されること | 認証失敗時にログイン画面へ留まり、認証失敗メッセージが表示されることを確認する。 |
| 3 | 機能性 | 入力妥当性 | ログイン入力値の必須・形式・桁数が検証されること | 組合員コードの必須、数値、6 桁以上 10 桁以下、パスワードの必須、8 文字以上 32 文字以下が検証されることを確認する。 |
| 4 | 使用性 | 操作起点の統一 | ログイン画面で Enter 操作でも認証処理を実行できること | ログインボタン押下と Enter 操作が同等に扱われることを確認する。 |
| 5 | 信頼性 | 二重送信防止 | ログイン送信中に再送できないこと | 認証 API 呼出中は送信ボタンが非活性となり、二重送信が防止されることを確認する。 |
| 6 | 機能性 | セッション確立 | ログイン成功時にセッションと CSRF トークンが払い出されること | ログイン成功時に後続画面遷移と更新 API に必要なセッション情報が確立されることを確認する。 |
| 7 | 信頼性 | セッション失効時挙動 | セッション切れ時にログイン画面へ復帰すること | 認証済み画面で API が 401 を返した場合に、期限切れメッセージ表示後、ログイン画面へ遷移することを確認する。 |
| 8 | セキュリティ | 未認証アクセス制御 | 未ログインで認証済み画面へアクセスできないこと | マイページ、お知らせ詳細、トップ画面などの認証済み機能が未認証状態では利用できないことを確認する。 |
| 9 | 機能性 | ログアウト処理 | 任意の認証済み画面からログアウトできること | ログアウト操作でセッションが破棄され、ログイン画面へ遷移することを確認する。 |
| 10 | セキュリティ | ログアウト後保護 | ログアウト後にブラウザ戻る等で保護画面を再利用できないこと | ログアウト後にブラウザバックや再読込をしても、保護対象情報へ復帰できないことを確認する。 |
| 11 | 機能性 | 一覧表示 | トップ画面に利用者情報とお知らせ一覧が表示されること | ログイン済み利用者に対して、利用者識別情報と公開対象のお知らせ一覧が取得・表示されることを確認する。 |
| 12 | 機能性 | 一覧空状態 | お知らせが 0 件でも異常扱いにならないこと | お知らせが存在しない場合にエラーではなく空状態メッセージが表示されることを確認する。 |
| 13 | 機能性 | 一覧並び順 | お知らせ一覧が設計どおりの順序で表示されること | お知らせ一覧が年度降順、公開日時降順の条件で表示されることを確認する。 |
| 14 | 機能性 | 一覧ページング | お知らせ一覧のページング条件が反映されること | page、pageSize の指定、既定値、上限値に基づいて一覧件数とページ情報が整合することを確認する。 |
| 15 | 機能性 | 公開条件制御 | 非公開または対象外のお知らせが一覧に表示されないこと | 公開条件を満たすお知らせのみが利用者に提示されることを確認する。 |
| 16 | 機能性 | 既読導線 | 一覧から選択したお知らせ詳細へ遷移できること | トップ画面から選択した noticeId を保持して詳細画面へ遷移できることを確認する。 |
| 17 | 機能性 | 詳細表示 | お知らせ詳細に受取状況・受取方法・明細情報が表示されること | 詳細 API の戻り値に基づき、受取状況、受取方法候補、注意事項、配当明細が欠落なく表示されることを確認する。 |
| 18 | 信頼性 | 詳細取得失敗時挙動 | 存在しないお知らせ指定時に安全に復帰できること | 指定したお知らせが存在しない場合に、エラーメッセージ表示後トップ画面へ復帰することを確認する。 |
| 19 | 機能性 | 変更可否制御 | 受取方法変更可否が画面状態に反映されること | canUpdateReceiptMethod や受取状態に応じて、受取方法が編集可能または読取専用として表示されることを確認する。 |
| 20 | 機能性 | 更新成立性 | 受取方法を正常に更新できること | 更新可能な条件下で、選択した受取方法が保存され、成功メッセージと更新後状態が画面へ反映されることを確認する。 |
| 21 | 機能性 | 更新入力妥当性 | 受取方法の必須・候補値制約が検証されること | 未選択や候補外の受取方法が入力された場合に、更新を受け付けず適切なエラーになることを確認する。 |
| 22 | 信頼性 | 業務条件エラー制御 | 受付期間外では受取方法を変更できないこと | 変更期限超過時に業務エラーメッセージが表示され、変更不可状態となることを確認する。 |
| 23 | 信頼性 | 状態遷移制御 | 受取済の配当では受取方法を変更できないこと | 受取状態が受取済の場合に変更操作が拒否され、読取専用表示となることを確認する。 |
| 24 | 信頼性 | 同一要求再送 | 同一受取方法の再送が冪等に扱われること | 同一内容の受取方法更新を再送しても、結果整合性が崩れないことを確認する。 |
| 25 | 機能性 | 画面戻り導線 | お知らせ詳細からトップ画面へ戻れること | 戻る操作で一覧画面へ復帰できることを確認する。 |
| 26 | 機能性 | 利用者情報表示 | マイページで利用者情報を参照できること | 組合員コード、氏名、生年月日、出資残高など参照項目と、編集対象項目が設計どおりに表示されることを確認する。 |
| 27 | 機能性 | 編集モード遷移 | マイページで表示モードと編集モードを切り替えられること | 編集開始操作により編集可能項目が入力可能となり、保存・キャンセル導線が有効になることを確認する。 |
| 28 | 機能性 | 編集権限制御 | マイページの読取専用項目は更新対象にならないこと | 氏名、生年月日、出資残高などの読取専用項目が編集不能であることを確認する。 |
| 29 | 機能性 | 更新成立性 | マイページの変更内容を正常に保存できること | 編集可能項目を更新した際に保存成功し、画面表示が最新値へ切り替わることを確認する。 |
| 30 | 機能性 | キャンセル制御 | マイページ編集のキャンセルで未保存変更が破棄されること | 編集途中でキャンセルした場合に保存前の表示状態へ戻ることを確認する。 |
| 31 | 機能性 | 入力妥当性 | 郵便番号、住所、電話番号、メールアドレスの形式・桁数が検証されること | 郵便番号 7 桁、住所 100 文字以内、電話番号 10 文字以上 13 文字以下、メールアドレス 254 文字以内などの条件が検証されることを確認する。 |
| 32 | 機能性 | 入力妥当性 | 通知方法の選択値制約が検証されること | 通知方法が定義済みの選択肢のみで保持されることを確認する。 |
| 33 | 機能性 | 任意入力制御 | 口座情報が任意入力として扱われること | 口座情報未入力でも保存可能であることを確認する。 |
| 34 | 信頼性 | 更新再送整合性 | 同一の利用者情報更新が冪等に扱われること | 同一内容の保存を再実行しても、状態や表示に不整合が発生しないことを確認する。 |
| 35 | セキュリティ | 認可制御 | 本人以外のデータ参照・更新が拒否されること | セッション利用者と異なる組合員データへの参照・更新要求が拒否されることを確認する。 |
| 36 | 信頼性 | 排他・整合性 | 受取方法更新時の競合が検知されること | 更新競合時に古い状態で上書きされず、再操作を促す制御となることを確認する。 |
| 37 | 信頼性 | 排他・整合性 | 利用者情報更新時に無効状態の更新が防止されること | 更新対象が既に無効または更新不可状態となった場合に、業務エラーとして扱われることを確認する。 |
| 38 | 機能性 | データ整合性 | 一覧・詳細・更新後表示のデータが矛盾しないこと | トップ画面、お知らせ詳細、マイページの各画面で取得・更新した情報が API 応答および永続化結果と整合することを確認する。 |
| 39 | 使用性 | メッセージ正当性 | 正常・異常メッセージが場面に応じて適切に表示されること | 認証失敗、セッション切れ、業務エラー、更新成功、空状態などのメッセージが設計どおりに表示されることを確認する。 |
| 40 | 使用性 | 入力支援 | 入力エラーが利用者に判別しやすい位置と粒度で表示されること | 項目単位または画面単位のエラー表示が、対象入力と対応付けて認識できることを確認する。 |
| 41 | 信頼性 | 例外復旧性 | システムエラー発生時に再試行可能な案内がされること | E_901 に該当する障害時に再試行案内が表示され、操作継続不能状態に陥らないことを確認する。 |
| 42 | 信頼性 | 通信異常時挙動 | 更新系 API のタイムアウト時に適切に失敗処理されること | 設計された応答時間を超過した場合に、更新結果が不明確なまま放置されず、失敗として利用者へ通知されることを確認する。 |
| 43 | セキュリティ | CSRF 対策 | 更新系操作に CSRF 保護が適用されること | POST、PUT、DELETE の更新系 API に対して、正当な CSRF トークンがない要求が受け付けられないことを確認する。 |
| 44 | セキュリティ | セッション Cookie 保護 | セッション Cookie が保護属性付きで扱われること | 認証後の Cookie が HttpOnly、Secure、SameSite の設計条件を満たすことを確認する。 |
| 45 | セキュリティ | 個人情報保護 | 個人情報応答がキャッシュ抑止されること | 個人情報を含む応答に対して no-store などのキャッシュ抑止ヘッダが設定されることを確認する。 |
| 46 | セキュリティ | 通信保護 | 個人情報を扱う通信が暗号化されること | ログイン、参照、更新の各通信が TLS 前提で保護されることを確認する。 |
| 47 | セキュリティ | 機微情報保護 | パスワードや機微情報がログへ出力されないこと | 認証情報、口座情報、メールアドレスなどの機微情報が運用ログに露出しないことを確認する。 |
| 48 | 機能性 | API 共通仕様 | 共通レスポンス形式とエラーコード運用が統一されること | 成功時・失敗時ともに定義済みレスポンス構造とエラーコード体系が一貫していることを確認する。 |
| 49 | 信頼性 | 追跡可能性 | API 要求が要求 ID で追跡できること | API 呼出に要求 ID が付与され、処理追跡や障害解析に利用できることを確認する。 |
| 50 | 性能 | 応答時間 | 参照系・更新系 API が設計上限時間内で応答すること | 参照系 10 秒、更新系 15 秒の設計目安に対して、主要なユーザー操作が許容時間内で完了することを確認する。 |
