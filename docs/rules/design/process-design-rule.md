# 処理設計ルール

# 基本方針

- 業務ロジックを明示する
- 処理順を明示する
- 条件分岐を明示する
- 呼出Repositoryを明示する
- エラー時動作を明示する
- 1 ステップごとの入力、分岐、DB 更新、外部 API 呼出が追える粒度で記載する

---

# 処理単位

- 1 つの処理では 1 つの業務責務だけを扱う
- 複数業務をまたぐ巨大な処理設計を避ける

---

# 処理記載ルール

以下を記載する

- 入力
- 出力
- 処理順
- 条件分岐
- DBアクセス
- エラー処理

---

# DBアクセス

- Repository単位で記載する
- 使用Collectionを明示する

---

# 条件分岐

- IF条件を明示する
- 正常系/異常系を分離する

---

# エラー制御

- ErrorCodeを記載する
- エラー条件を記載する

---

# トランザクション

- 必要な場合のみ明示する
- 更新順を明示する

---

# 設計時注意事項

- 処理を省略しない
- 「適切に処理する」「必要に応じて実行する」などの曖昧表現を記載しない
- DB更新条件を明示する
- 外部API呼出を明示する

---

# 禁止事項

- 画面表示や入力操作などの UI 処理を混在させること
- Repository を経由しない SQL を直接記載すること
- プログラミング言語の実装コードをそのまま記載すること
- 「適切に処理する」「必要に応じて実行する」などの曖昧表現
- 複数責務をまとめた巨大な処理設計
