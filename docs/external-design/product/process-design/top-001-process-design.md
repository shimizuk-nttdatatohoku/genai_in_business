# TOP_001 トップ画面表示 処理設計書

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | TOP_001 |
| 機能名 | トップ画面表示 |
| 目的/ゴール | ログイン済み組合員へ出資配当金お知らせ一覧とマイページ入口を表示する。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | ログイン成功後の初回表示、または戻る遷移でトップ画面表示 |
| 入力 | セッション Cookie、一覧ページ番号、notice_id 選択 |
| 出力 | お知らせ一覧、組合員コード、ログイン名、New 表示、マイページ遷移入口 |
| 前提条件 | ログイン済みセッションが有効であること。 |
| 関連画面 | SCR-002 トップ画面、SCR-003 出資配当金お知らせ画面、SCR-004 マイページ画面 |
| 関連IF | IF-003 出資配当金お知らせ一覧取得、IF-006 組合員情報取得、IF-002 ログアウト |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| セッション Cookie | string | Y | 有効セッションであること | ブラウザ保持値 |
| page | integer | N | 1 以上 | 1 |
| pageSize | integer | N | 1..20 | 20 |
| X-Request-Id | string | Y | UUID 形式 | クライアント生成 |

### 2.2 出力項目

| 項目名 | 型 | 説明 |
|---|---|---|
| userCode | string | ヘッダ表示用組合員コード |
| loginName | string | ヘッダ表示用ログイン名 |
| notices | array | お知らせ一覧 |
| noticeId | string | お知らせ識別子 |
| fiscalYear | string | 年度 |
| title | string | お知らせタイトル |
| isNew | boolean | New ラベル表示判定 |
| totalCount | integer | 総件数 |
| ページング状態 | object | 現在ページ、総ページ数 |

### 2.3 画面状態

| 状態 | 内容 |
|---|---|
| loading | 一覧エリアをスケルトン表示 |
| loaded | 一覧または空状態メッセージを表示 |
| paging | ページ切替中。対象操作を一時非活性 |
| error | エラーメッセージを表示 |

## 3. 正常系処理フロー

1. UI はトップ画面表示開始時に loading 状態へ遷移する。
2. UI は GET /api/v1/dividend-notices を送信し、対象組合員に公開中のお知らせ一覧を取得する。
3. NoticeController はセッションを検証し、NoticeService へ一覧取得を依頼する。
4. NoticeService は DividendNoticeRepository.dividend_notices を参照し、対象組合員向け公開中データを年度降順・更新日時降順で取得する。
5. NoticeService は既読情報が存在する場合、NoticeReadRepository.notice_reads を参照して isNew を判定する。
6. NoticeController は一覧データを返却する。
7. UI は一覧データを描画し、件数 0 の場合は空状態メッセージを表示する。
8. 組合員がお知らせタイトルを押下した場合、UI は選択した noticeId を画面状態に保持して SCR-003 へ遷移する。
9. 組合員がマイページリンクを押下した場合、UI は SCR-004 へ遷移する。

### 3.1 トランザクション境界

| 境界 | 内容 |
|---|---|
| TX-01 | 一覧取得は参照トランザクションとして扱う |

## 4. 例外/エラー処理

### 4.1 認証・認可エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_001 | セッション無効、タイムアウト | 「セッションの有効期限が切れました」を表示して SCR-001 へ遷移 | 再ログイン |
| E_002 | 本人以外のデータ参照要求 | 403 相当の共通エラー表示 | 正常なログイン後に再表示 |

### 4.2 業務エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_404 | 選択したお知らせが遷移時点で非公開または削除済み | 一覧上部に「お知らせが見つかりません」を表示し一覧再取得 | 再選択 |

### 4.3 システムエラー

| エラーコード | 検知条件 | ユーザー通知 | 処理 |
|---|---|---|---|
| E_901 | 一覧取得失敗、DB 障害、タイムアウト | 一覧上部に「時間をおいて再度お試しください」を表示 | loading を解除し再試行可能状態へ戻す |

## 5. データ更新・整合性

| 項目 | 内容 |
|---|---|
| 参照データ | `dividend_notices`、`notice_reads`、セッション情報 |
| 更新データ | 本機能単体では DB 更新なし |
| 使用 Repository | DividendNoticeRepository、NoticeReadRepository |
| 参照順序 | 1. セッション検証 2. お知らせ一覧取得 3. 既読情報参照 |
| 整合性ルール | 非公開データ、他組合員向けデータは返却しない |
| 冪等性 | あり。同一条件の再取得で同一結果を返す |
| 排他 | 参照系のため排他制御なし |

## 6. ログ/監査/運用観点

| 観点 | 内容 |
|---|---|
| 操作ログ | request_id、endpoint、method、user_code、取得件数 |
| 監査ログ | お知らせ詳細遷移時の notice_id、user_code |
| エラーログ | request_id、例外種別、stacktrace |
| 性能観点 | 1 ページ 20 件、最大 100 件を上限とし、一覧応答は 10 秒以内を目標とする |
| 運用観点 | 非公開切替済みデータは一覧取得対象から除外する |

## 7. 前提・要確認事項

- 前提: New ラベルは未確認お知らせに対して表示する。
- 要確認: 既読管理を行う場合の既読更新タイミングを、詳細表示時か一覧表示時かで確定する。
