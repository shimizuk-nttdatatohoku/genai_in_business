# DIV_002 配当金受取方法変更 処理設計書

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | DIV_002 |
| 機能名 | 配当金受取方法変更 |
| 目的/ゴール | 当年の配当金受取方法を組合員本人が変更し、変更結果を即時反映する。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | 出資配当金お知らせ画面で配当金受取方法を変更し、確定ボタン押下 |
| 入力 | noticeId、配当金受取方法、セッション Cookie、CSRF トークン |
| 出力 | 更新結果、最新の受取方法、成功メッセージまたはエラーメッセージ |
| 前提条件 | ログイン済みであること。対象お知らせが本人データであり、受付期間内かつ未受取であること。 |
| 関連画面 | SCR-003 出資配当金お知らせ画面 |
| 関連IF | IF-005 配当金受取方法更新 |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| noticeId | string | Y | 選択中のお知らせであること | 画面保持値 |
| receiptMethod | string | Y | マスタ値内であること | 画面表示中の現在値 |
| セッション Cookie | string | Y | 有効セッションであること | ブラウザ保持値 |
| X-CSRF-Token | string | Y | サーバー払い出し済みであること | 画面保持値 |
| X-Request-Id | string | Y | UUID 形式 | クライアント生成 |

### 2.2 出力項目

| 項目名 | 型 | 説明 |
|---|---|---|
| noticeId | string | 更新対象識別子 |
| receiptMethod | string | 更新後の配当金受取方法 |
| receiptStatus | string | 更新後の受取状況 |
| updatedAt | string | 更新日時 |
| successMessage | string | 「配当金受取方法を更新しました」 |
| errorMessage | string | 業務エラーまたはシステムエラー表示文言 |

### 2.3 画面状態

| 状態 | 内容 |
|---|---|
| editable | セレクト編集可、確定ボタン活性 |
| validating | 入力チェック中 |
| submitting | 更新 API 呼出中。確定ボタン非活性 |
| success | 最新値を再表示し成功メッセージ表示 |
| error | エラーメッセージ表示、確定ボタン再活性 |

## 3. 正常系処理フロー

1. 組合員が配当金受取方法を変更する。
2. UI は選択値が未選択でないこと、候補値内であることを確認する。
3. UI は確定ボタン押下時に PUT /api/v1/dividend-notices/{noticeId}/receipt-method を送信する。
4. NoticeController はセッションと CSRF トークンを検証する。
5. NoticeController は RequestValidationService で `receiptMethod` の必須・候補値チェックを行う。
6. DividendService は DistributionRepository.distributions から対象組合員の当年配当情報を取得する。
7. DividendService は以下の業務条件を判定する。
   - noticeId が本人に紐づくこと
   - 変更受付期間内であること
   - 配当金受取状況が未受取であること
8. 業務条件 OK の場合、DividendService は `distributions` の受取方法を更新する。
9. DividendService は更新後データを再取得し、最新値を返却する。
10. UI は成功メッセージを表示し、受取方法、受取状況、説明文を再描画する。

### 3.1 トランザクション境界

| 境界 | 内容 |
|---|---|
| TX-01 | `distributions` の対象レコード取得から受取方法更新までを 1 トランザクションで実施する |
| TX-02 | 更新後再取得は別参照トランザクションとする |

## 4. 例外/エラー処理

### 4.1 入力エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_101 | receiptMethod 未選択 | 項目下に「配当金受取方法は必須です」を表示 | 選択後に再実行 |
| E_102 | 候補外の値 | 項目下に形式エラー表示 | 正しい候補を選択して再実行 |

### 4.2 認証・認可・業務エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_001 | セッション無効、タイムアウト | 「セッションの有効期限が切れました」を表示して SCR-001 へ遷移 | 再ログイン |
| E_002 | 他組合員データへの更新要求 | 403 相当の共通エラー表示 | 正常なログイン状態から再表示 |
| E_201 | 変更受付期間外 | 受取情報エリア上部に「受付期間外のため変更できません」を表示 | 画面再表示のみ |
| E_202 | 受取済のため変更不可 | 受取情報エリア上部に「受取済のため変更できません」を表示し、入力欄を読取専用にする | 画面再表示のみ |
| E_404 | noticeId 不正 | トップ画面へ戻し「お知らせが見つかりません」を表示 | 一覧再選択 |

### 4.3 システムエラー

| エラーコード | 検知条件 | ユーザー通知 | 処理 |
|---|---|---|---|
| E_901 | 更新失敗、DB 障害、タイムアウト | 受取情報エリア上部に「時間をおいて再度お試しください」を表示 | 変更前値を保持し、確定ボタンを再活性化する |

## 5. データ更新・整合性

| 項目 | 内容 |
|---|---|
| 参照データ | `distributions`、`dividend_notices`、`receipt_method_master` |
| 更新データ | `distributions` の receipt_method、updated_at |
| 使用 Repository | DistributionRepository、DividendNoticeRepository、ReceiptMethodMasterRepository |
| 更新順序 | 1. 本人データ確認 2. 業務条件判定 3. 受取方法更新 4. 更新後再取得 |
| 整合性ルール | 受取済または受付期間外の場合は更新しない |
| 冪等性 | 同一 noticeId に対し同一 receiptMethod を再送しても最終状態が同一であれば成功扱いとする |
| 排他 | 同一組合員・同一年度の受取方法更新は楽観ロックで制御し、version または updated_at 不一致時は E_201 相当の再表示とする |

## 6. ログ/監査/運用観点

| 観点 | 内容 |
|---|---|
| 操作ログ | request_id、endpoint、method、user_code、notice_id、変更前受取方法、変更後受取方法、結果 |
| 監査ログ | 更新者、更新日時、対象年度、対象 distribution_id |
| エラーログ | request_id、例外内容、stacktrace |
| マスキング | 個人口座情報は出力しない |
| 性能観点 | 更新 API 応答は 15 秒以内を目標とする |

## 7. 前提・要確認事項

- 前提: 変更可能な受取方法候補はマスタ管理とする。
- 要確認: 楽観ロック衝突時の専用エラーコード要否。
- 要確認: 更新確定前の確認ダイアログ有無。
