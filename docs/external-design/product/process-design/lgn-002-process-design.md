# LGN_002 ログアウト 処理設計書

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | LGN_002 |
| 機能名 | ログアウト |
| 目的/ゴール | 現在のログインセッションを安全に破棄し、ログイン画面へ遷移させる。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | トップ画面、出資配当金お知らせ画面、マイページ画面でログアウトボタン押下 |
| 入力 | セッション Cookie、CSRF トークン |
| 出力 | ログアウト結果、ログイン画面遷移 |
| 前提条件 | ログイン済みセッションが有効であること。 |
| 関連画面 | SCR-002、SCR-003、SCR-004、SCR-001 |
| 関連IF | IF-002 ログアウト |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| セッション Cookie | string | Y | 有効なセッション ID を含むこと | ブラウザ保持値 |
| X-CSRF-Token | string | Y | サーバー払い出し済みであること | 画面保持値 |
| X-Request-Id | string | Y | UUID 形式 | クライアント生成 |

### 2.2 出力項目

| 項目名 | 型 | 説明 |
|---|---|---|
| loggedOutAt | string | ログアウト完了日時 |
| 遷移先画面 | string | ログイン画面 |
| エラーメッセージ | string | ログアウト失敗時に画面上部へ表示 |

### 2.3 画面状態

| 状態 | 内容 |
|---|---|
| ready | ログアウトボタン活性 |
| submitting | ログアウト API 呼出中。ボタン非活性 |
| completed | セッション破棄済み。SCR-001 へ遷移 |
| error | エラーメッセージ表示、ボタン再活性 |

## 3. 正常系処理フロー

1. 組合員が各画面のログアウトボタンを押下する。
2. UI は多重送信防止のためログアウトボタンを非活性化する。
3. UI は DELETE /api/v1/auth-sessions/current を送信する。
4. AuthController はセッション Cookie と CSRF トークンを検証する。
5. AuthService は AuthSessionRepository.auth_sessions から現行セッションを取得する。
6. AuthService は対象セッションを無効化または削除する。
7. AuthController はセッション Cookie を失効させるレスポンスを返却する。
8. UI は保持中の userCode、loginName、csrfToken、notice_id を破棄する。
9. UI は SCR-001 ログイン画面へ遷移する。

### 3.1 トランザクション境界

| 境界 | 内容 |
|---|---|
| TX-01 | `auth_sessions` の取得と削除または無効化を 1 トランザクションで実施する |

## 4. 例外/エラー処理

### 4.1 入力/認証エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_001 | セッション無効、タイムアウト、Cookie 不正 | ログイン画面へ遷移し「セッションの有効期限が切れました」を表示する | 再ログイン |
| E_002 | CSRF トークン不正、本人以外のセッション操作 | 403 相当画面または共通エラー表示 | 正常な画面遷移から再操作 |

### 4.2 システムエラー

| エラーコード | 検知条件 | ユーザー通知 | 処理 |
|---|---|---|---|
| E_901 | セッション削除失敗、DB 障害、タイムアウト | 画面上部に「ログアウトに失敗しました」を表示 | 画面に留まり、ログアウトボタンを再活性化する |

## 5. データ更新・整合性

| 項目 | 内容 |
|---|---|
| 参照データ | `auth_sessions` コレクションの現行セッション |
| 更新データ | `auth_sessions` コレクションの対象セッション |
| 使用 Repository | AuthSessionRepository |
| 更新順序 | 1. セッション検証 2. セッション無効化または削除 3. Cookie 失効 |
| 整合性ルール | セッション無効化と Cookie 失効の両方が完了した場合のみ成功とする |
| 冪等性 | あり。同一セッションに対する再実行時は結果を成功として扱ってよい |
| 排他 | 同一セッションへの同時ログアウトは最後の 1 回のみ実更新される |

## 6. ログ/監査/運用観点

| 観点 | 内容 |
|---|---|
| 操作ログ | request_id、endpoint、method、user_code、session_id、結果 |
| 監査ログ | ログアウト日時、session_id、user_code |
| エラーログ | request_id、例外内容、stacktrace |
| マスキング | Cookie 値、CSRF トークンは平文出力しない |
| 性能観点 | ログアウト API 応答は 5 秒以内を目標とする |

## 7. 前提・要確認事項

- 前提: 画面遷移時にブラウザの履歴から個人情報画面を再表示しないようキャッシュ抑止を行う。
- 要確認: セッション削除方式を物理削除と論理無効化のどちらに統一するか。
