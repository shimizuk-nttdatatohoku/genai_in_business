# 処理設計書

**ファイルパス**: `docs/ED/product/MYP_001_process-design.md`

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | MYP_001 |
| 機能名 | マイページ（組合員情報表示） |
| 目的/ゴール | 登録済みの組合員情報を参照し、変更可能項目を更新できるようにする。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | トップ画面のマイページリンククリック、マイページ画面の初期表示、編集ボタンクリック、保存ボタンクリック |
| 入力 | セッション情報、編集対象の組合員情報 |
| 出力 | 組合員情報詳細、更新結果、確認メッセージ |
| 前提条件 | ログイン済みであること。対象は本人データのみであること。 |

## 3. 処理フロー（正常系）

1. 利用者がトップ画面からマイページリンクをクリックする。
2. 画面初期表示時にマイページ情報取得APIを呼び出す。
3. APIはセッションを検証し、本人の組合員基本情報、連絡先情報、通知方法、出資金残高、配当金受取方法、口座登録状態を取得する。
4. フロントエンドは閲覧モードで情報を表示する。
5. 利用者が編集ボタンをクリックすると、画面状態を `edit` に変更する。
6. 編集可能項目に対して利用者が値を入力する。
7. 利用者が保存ボタンをクリックすると、クライアント側バリデーションを実施する。
8. バリデーション正常時、更新APIを呼び出し、画面状態を `saving` に変更する。
9. APIは対象レコードの `record_version` を確認し、更新対象項目のみを条件付き更新する。
10. 更新成功後、最新値を返却し、フロントエンドは閲覧モードに戻して「更新しました」を表示する。

### 3.1 分岐条件

| 条件 | 結果 |
|---|---|
| 初期表示のみ | 閲覧モードで表示 |
| 編集ボタンクリック | 編集モードへ切替 |
| 入力エラーあり | 保存せず編集モード継続 |
| 更新成功 | 閲覧モードへ戻す |
| 同時更新あり | 再読込を促す |

### 3.2 画面遷移

| 遷移元 | 条件 | 遷移先 |
|---|---|---|
| トップ画面 | マイページリンククリック | マイページ画面 |
| マイページ画面 | 保存成功 | マイページ画面 |
| マイページ画面 | 戻るクリック | トップ画面 |
| マイページ画面 | ログアウトクリック | ログイン画面 |

### 3.3 トランザクション境界

| 開始 | 終了 | 内容 |
|---|---|---|
| 情報取得API開始時 | レスポンス返却時 | 参照専用処理 |
| 更新API開始時 | 組合員情報更新完了時 | 入力チェック後、更新対象項目のみ単一論理トランザクションで更新 |

## 5. 例外/エラー処理

### 5.1 入力エラー

| 検知条件 | エラーコード | 表示内容 | 復帰方法 |
|---|---|---|---|
| 郵便番号形式不正 | E_102 | 「郵便番号は7桁の数字で入力してください」 | 該当項目を修正 |
| 電話番号形式不正 | E_102 | 「電話番号は10桁または11桁の数字で入力してください」 | 該当項目を修正 |
| メール形式不正 | E_102 | 「メールアドレスの形式で入力してください」 | 該当項目を修正 |

### 5.2 業務エラー

| 検知条件 | エラーコード | 表示内容 | 処理 |
|---|---|---|---|
| 本人以外のデータ更新要求 | E_202 | 「更新対象が不正です」 | 更新せずログイン画面または403へ |
| 同時更新検知 | E_205 | 「他の操作で更新されました。再表示します」 | 最新値を再取得 |
| 変更禁止項目の更新要求 | E_206 | 「変更できない項目が含まれています」 | 更新せず画面に留まる |

### 5.3 システムエラー

| 検知条件 | エラーコード | リトライ | 表示内容 | ログ |
|---|---|---|---|---|
| DB取得/更新タイムアウト | E_901 | 再試行可 | 「処理に失敗しました。時間をおいて再度お試しください」 | request_id、endpoint、method、user_id、stacktrace |
| 未処理例外 | E_999 | 再試行可 | 「システムエラーが発生しました」 | 同上 |

### 5.4 セッション切れ/権限不足

| 事象 | エラーコード | 処理 |
|---|---|---|
| セッション切れ | E_003 | ログイン画面へ遷移し、未保存変更は破棄 |
| 権限不足 | E_004 | 403相当画面またはログイン画面へ遷移 |

## 6. データ更新・整合性

| 区分 | 内容 |
|---|---|
| 参照データ | 組合員基本情報、連絡先情報、通知方法、出資金残高、配当金受取方法、口座登録情報 |
| 更新データ | 組合員連絡先情報、通知方法 |
| 更新順序 | 1. セッション確認 2. 本人確認 3. バージョン確認 4. 編集可能項目のみ更新 |
| 整合性ルール | 更新可能なのは本人の連絡先・通知方法のみ。出資金残高、配当金受取方法、口座登録情報は参照専用 |
| 排他 | 楽観ロックを採用し、`record_version` 一致時のみ更新する |
| 冪等性 | 同一内容の再送は成功扱い。差分なし更新は更新日時を変更しない前提 |

## 7. ログ/監査/運用観点

| 区分 | 記録内容 |
|---|---|
| 操作ログ | request_id、機能ID、組合員コード、更新対象項目、結果、実行日時 |
| 監査ログ | 個人情報更新として、変更前後値、更新者、更新日時を記録 |
| 障害解析 | request_id、endpoint、method、stacktrace、user_id |
| 性能観点 | 初期表示3秒以内、更新処理3秒以内を目標。マイページは単一利用者データのみ取得し一覧検索は行わない |

## 8. 前提

- 画面イメージより、出資金残高、配当金受取方法、口座登録情報は参照専用とする。
- 住所欄に「こちら」リンクが表示されているため、住所変更を本画面で直接更新するか別導線とするかは未確定である。本設計では要件定義を優先し、住所・郵便番号を更新対象に含めた。

## 9. 要確認事項

- 組合員名、フリガナを編集対象に含めるか。
- 住所変更を別手続導線とする場合の機能分割。
