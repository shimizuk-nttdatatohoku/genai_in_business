# 処理設計書

**ファイルパス**: `docs/ED/product/LGN_001_process-design.md`

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | LGN_001 |
| 機能名 | ログイン |
| 目的/ゴール | 組合員コードとパスワードで利用者を認証し、認証成功時にトップ画面へ遷移させる。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | SCR-001 ログイン画面の初期表示、組合員コード入力、パスワード入力、ログインボタンクリック |
| 入力 | 組合員コード、パスワード |
| 出力 | 認証結果、エラーメッセージ、セッション情報、トップ画面への遷移 |
| 前提条件 | 未ログイン状態であること。利用者が有効な組合員アカウントを保有していること。通信は HTTPS であること。 |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| 組合員コード | string | Y | 7桁数字、前後空白除去後に判定 | 空文字 |
| パスワード | string | Y | 8文字以上32文字以下、英数字記号可、前後空白は入力値として保持 | 空文字 |
| request_id | string | Y | サーバー側で採番する相関ID | なし |

### 2.2 出力項目

| 項目名 | 型 | 内容 |
|---|---|---|
| login_result | boolean | 認証成功時 `true`、失敗時 `false` |
| session_id | string | 認証成功時に払い出すセッション識別子 |
| user_code | string | ログイン済み利用者の組合員コード |
| login_name | string | ヘッダ表示用の利用者名 |
| redirect_path | string | 成功時はトップ画面、失敗時はログイン画面 |
| message | string | 画面表示メッセージ。エラーコード自体は画面表示しない |

### 2.3 画面状態

| 状態名 | 内容 |
|---|---|
| initial | 未入力状態。ログインボタンは活性 |
| validating | クライアント側入力チェック中 |
| authenticating | API呼出中。ログインボタンは非活性、二重送信不可 |
| success | 認証成功。トップ画面へ遷移 |
| error | 認証失敗または入力エラー。入力値を保持しパスワードのみクリア |

## 3. 処理フロー（正常系）

1. 画面初期表示時、未ログイン状態であることを確認し、入力欄を空で表示する。
2. 利用者が組合員コードとパスワードを入力し、ログインボタンをクリックする。
3. クライアント側で必須チェックと形式チェックを実施する。
4. バリデーションが正常な場合、画面状態を `authenticating` に変更し、ログインボタンを非活性にする。
5. 認証APIは `request_id` を採番し、組合員コードに紐づく認証情報を取得する。
6. 対象アカウントの存在、有効状態、パスワード一致を判定する。
7. 認証成功時、セッション情報を新規作成し、利用者の基本情報をセッションに格納する。
8. 認証結果を成功で返却し、フロントエンドはトップ画面へ遷移する。

### 3.1 分岐条件

| 条件 | 結果 |
|---|---|
| 組合員コード、パスワードが形式不正 | API呼出を行わず入力エラー表示 |
| 認証成功 | トップ画面へ遷移 |
| 認証失敗 | ログイン画面に留まりエラー表示 |

### 3.2 画面遷移

| 遷移元 | 条件 | 遷移先 |
|---|---|---|
| ログイン画面 | 認証成功 | トップ画面 |
| ログイン画面 | 認証失敗 | ログイン画面 |

### 3.3 トランザクション境界

| 開始 | 終了 | 内容 |
|---|---|---|
| 認証API開始時 | セッション作成完了時 | 認証判定とセッション作成を同一論理トランザクションとする |

## 4. 入力チェック

| 項目 | チェック内容 | エラーコード | 画面表示 |
|---|---|---|---|
| 組合員コード | 未入力 | E_101 | 「組合員コードは必須です」 |
| 組合員コード | 7桁数字以外 | E_102 | 「組合員コードは7桁の数字で入力してください」 |
| パスワード | 未入力 | E_101 | 「パスワードは必須です」 |
| パスワード | 8文字未満または32文字超過 | E_103 | 「パスワードは8文字以上32文字以下で入力してください」 |

## 5. 例外/エラー処理

### 5.1 入力エラー

| 検知条件 | エラーコード | 表示内容 | 復帰方法 |
|---|---|---|---|
| 必須未入力 | E_101 | 該当項目の直下にメッセージ表示 | 該当項目を再入力 |
| 形式不正 | E_102/E_103 | 該当項目の直下にメッセージ表示 | 該当項目を再入力 |

### 5.2 業務エラー

| 検知条件 | エラーコード | 表示内容 | 処理 |
|---|---|---|---|
| 組合員コード未登録 | E_001 | 「組合員コードまたはパスワードが正しくありません」 | パスワードをクリアして再入力待ち |
| パスワード不一致 | E_001 | 「組合員コードまたはパスワードが正しくありません」 | 同上 |
| アカウント無効 | E_002 | 「このアカウントは利用できません」 | ログイン画面に留める |

### 5.3 システムエラー

| 検知条件 | エラーコード | リトライ | 表示内容 | ログ |
|---|---|---|---|---|
| 認証基盤タイムアウト | E_901 | 利用者による再試行可 | 「時間をおいて再度お試しください」 | request_id、endpoint、method、user_id、stacktrace |
| DB接続障害 | E_902 | 利用者による再試行可 | 「システムエラーが発生しました」 | 同上 |
| 未処理例外 | E_999 | 利用者による再試行可 | 「システムエラーが発生しました」 | 同上 |

### 5.4 セッション切れ/権限不足

| 事象 | エラーコード | 処理 |
|---|---|---|
| セッション切れ状態でログイン済み画面から遷移 | E_003 | 既存セッションを破棄しログイン画面へ遷移 |
| 組合員以外の権限で利用 | E_004 | 403相当画面またはログイン画面へ遷移 |

## 6. データ更新・整合性

| 区分 | 内容 |
|---|---|
| 参照データ | 認証情報、組合員基本情報 |
| 更新データ | セッション情報 |
| 更新順序 | 1. 認証情報参照 2. 組合員状態確認 3. セッション作成 |
| 整合性ルール | 認証成功時のみセッションを作成する。認証失敗時は更新しない |
| 排他 | セッション作成は同一利用者で複数回実行されても後勝ち許容とする。旧セッションの失効方式は要確認 |
| 冪等性 | 同一認証要求の再送時は最新セッションを有効とし、重複ログイン自体は許容する前提 |

## 7. ログ/監査/運用観点

| 区分 | 記録内容 |
|---|---|
| 操作ログ | request_id、機能ID、組合員コード、実行結果、実行日時、送信元IP |
| 監査ログ | 認証成功/失敗、失敗理由分類、セッションID |
| 障害解析 | request_id、endpoint、method、stacktrace、user_id |
| 性能観点 | 認証応答は3秒以内を目標、失敗回数制御の導入有無は要確認 |

## 8. 前提

- 認証APIのURLは画面設計書に合わせて `/api/v1/login` を想定する。

## 9. 要確認事項

- 同一利用者の同時ログインを許可するか。
- パスワード誤入力回数によるアカウントロックを導入するか。
