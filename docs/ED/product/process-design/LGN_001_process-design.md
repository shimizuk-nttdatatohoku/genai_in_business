# LGN_001 ログイン 処理設計書

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | LGN_001 |
| 機能名 | ログイン |
| 目的/ゴール | 組合員コードとパスワードを認証し、認証済みセッションを開始してトップ画面へ遷移させる。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | ログイン画面初期表示後、ログインボタン押下またはパスワード入力欄で Enter 実行 |
| 入力 | 組合員コード、パスワード |
| 出力 | 認証結果、セッション情報、CSRF トークン、エラーメッセージ |
| 前提条件 | 未ログイン状態であること。TLS 通信が有効であること。 |
| 関連画面 | SCR-001 ログイン画面、SCR-002 トップ画面 |
| 関連IF | IF-001 ログイン |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| 組合員コード | string | Y | 半角数字 6..10 桁、前後空白除去後に判定 | 空 |
| パスワード | string | Y | 8..32 文字、マスク表示 | 空 |
| X-Request-Id | string | Y | UUID 形式 | クライアント生成 |

### 2.2 出力項目

| 項目名 | 型 | 説明 |
|---|---|---|
| sessionId | string | セッション識別子 |
| userCode | string | ログイン済み組合員コード |
| loginName | string | ヘッダ表示用氏名 |
| csrfToken | string | 状態変更 API 用トークン |
| lastLoginAt | string | 前回ログイン日時（ISO8601） |
| エラーメッセージ | string | 認証失敗時または入力エラー時に表示 |

### 2.3 画面状態

| 状態 | 内容 |
|---|---|
| initial | 入力欄は空、エラー表示なし、ログインボタン活性 |
| validating | クライアント入力チェック中 |
| submitting | API 呼出中。ログインボタン非活性、二重送信禁止 |
| error | フォーム上部または項目下にエラー表示 |
| authenticated | セッション開始済み。SCR-002 へ遷移 |

## 3. 正常系処理フロー

1. UI はログイン画面初期表示時に組合員コード入力欄へフォーカスを設定する。
2. 組合員が組合員コードとパスワードを入力し、ログイン操作を実行する。
3. UI は以下の入力チェックを行う。
   - 組合員コードが未入力でないこと
   - 組合員コードが半角数字 6..10 桁であること
   - パスワードが未入力でないこと
   - パスワード長が 8..32 文字であること
4. 入力チェック OK の場合、UI はログインボタンを非活性化し、POST /api/v1/auth-sessions を送信する。
5. AuthController はリクエストを受領し、RequestValidationService で必須・形式チェックを再実施する。
6. AuthController は AuthRepository.users を参照し、組合員コードに対応する認証情報を取得する。
7. AuthService は受領したパスワードをハッシュ化比較し、認証可否を判定する。
8. 認証成功時、AuthService は AuthSessionRepository.auth_sessions に新規セッションを登録する。
9. AuthService は CSRF トークンを生成し、セッション情報へ紐付けて保存する。
10. AuthController は `Set-Cookie` により HttpOnly、Secure、SameSite=Lax のセッション Cookie を設定し、201 を返却する。
11. UI はレスポンスから userCode、loginName を保持し、SCR-002 トップ画面へ遷移する。

### 3.1 トランザクション境界

| 境界 | 内容 |
|---|---|
| TX-01 | `users` 参照は参照トランザクションとして扱う |
| TX-02 | 認証成功後の `auth_sessions` 登録と CSRF トークン保存を 1 トランザクションでコミットする |

## 4. 例外/エラー処理

### 4.1 入力エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_101 | 組合員コード未入力、パスワード未入力 | 各項目下に必須メッセージを表示 | 入力値修正後に再実行 |
| E_102 | 組合員コード桁数不正、半角数字以外、パスワード文字数不正 | 各項目下に形式エラーメッセージを表示 | 入力値修正後に再実行 |

### 4.2 業務エラー

| エラーコード | 検知条件 | 表示内容 | 復帰方法 |
|---|---|---|---|
| E_001 | 組合員コードとパスワードの組み合わせ不一致 | フォーム上部に「組合員コードまたはパスワードが正しくありません」を表示し、パスワードをクリアする | 組合員が再入力して再実行 |

### 4.3 システムエラー

| エラーコード | 検知条件 | ユーザー通知 | 処理 |
|---|---|---|---|
| E_901 | DB 接続障害、タイムアウト、セッション保存失敗 | フォーム上部に「時間をおいて再度お試しください」を表示 | セッションは開始しない。ボタンを再活性化する |

## 5. データ更新・整合性

| 項目 | 内容 |
|---|---|
| 参照データ | `users` コレクションの認証情報 |
| 更新データ | `auth_sessions` コレクションのセッション情報、CSRF トークン |
| 使用 Repository | AuthRepository、AuthSessionRepository |
| 更新順序 | 1. 認証情報参照 2. パスワード照合 3. セッション登録 4. CSRF トークン保存 |
| 整合性ルール | 認証失敗時は `auth_sessions` を更新しない |
| 冪等性 | なし。同一入力の連続送信は別セッションが生成され得るため UI 側で二重送信防止を行う |
| 排他 | 同一組合員の多重ログインは許容する前提。排他制御は行わない |

## 6. ログ/監査/運用観点

| 観点 | 内容 |
|---|---|
| 操作ログ | request_id、endpoint、method、user_code、認証結果 |
| 監査ログ | セッション作成日時、session_id、user_code、client_ip |
| エラーログ | request_id、例外種別、stacktrace、user_code（取得可能時のみ） |
| マスキング | パスワードはログ出力しない |
| 性能観点 | 認証 API 応答は 10 秒以内を目標とする |

## 7. 前提・要確認事項

- 前提: アカウントロック要件は現時点では未定義とする。
- 要確認: 同一組合員の同時セッション数制限要否。
- 要確認: 認証失敗回数の監査ログ保持期間。
