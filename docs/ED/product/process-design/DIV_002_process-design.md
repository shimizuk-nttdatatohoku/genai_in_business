# 処理設計書

**ファイルパス**: `docs/ED/product/DIV_002_process-design.md`

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | DIV_002 |
| 機能名 | 配当金受取方法変更 |
| 目的/ゴール | 当年の配当金について、利用者が受取方法を変更し保存できるようにする。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | SCR-003 出資配当金お知らせ画面で受取方法を選択し、確定ボタンをクリック |
| 入力 | notice_id、選択受取方法、画面保持バージョン |
| 出力 | 更新結果、確認メッセージ、更新後の受取方法 |
| 前提条件 | ログイン済みであること。対象年度が当年であり、受取状況が未受取であること。 |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| session_id | string | Y | 有効セッションであること | セッション保持値 |
| notice_id | string | Y | 表示中お知らせID | URLまたは画面状態 |
| receipt_method | enum | Y | 出資振替 / 登録口座振込 / 現金受取 | 画面表示中の現在値 |
| record_version | string | Y | 楽観ロック用バージョン | 画面初期表示時取得値 |

### 2.2 出力項目

| 項目名 | 型 | 内容 |
|---|---|---|
| update_result | boolean | 更新成功時 `true` |
| updated_receipt_method | enum | 更新後の受取方法 |
| message | string | 成功時は「更新しました」 |
| next_state | string | success / error |

### 2.3 画面状態

| 状態名 | 内容 |
|---|---|
| view | 初期表示状態 |
| editing | 受取方法選択後、未保存状態 |
| saving | 更新API呼出中。確定ボタン非活性 |
| saved | 更新完了。最新値を再表示 |
| error | 更新失敗 |

## 3. 処理フロー（正常系）

1. 利用者が出資配当金お知らせ画面で受取方法を選択する。
2. フロントエンドは画面状態を `editing` に変更し、変更有無を保持する。
3. 利用者が確定ボタンをクリックする。
4. クライアント側で未選択チェックを実施する。
5. バリデーション正常時、更新APIを呼び出し、画面状態を `saving` に変更する。
6. APIはセッションを検証し、対象 `notice_id` に紐づく当年の配当受取方法レコードを取得する。
7. 対象レコードについて、受取状況が未受取であること、更新対象年度が当年であること、`record_version` が一致することを確認する。
8. 選択値が現在値と同一の場合は更新不要として成功扱いで返却する。
9. 選択値が異なる場合は受取方法を更新し、更新日時と更新者を記録する。
10. 更新成功後、フロントエンドは最新値を表示し、「更新しました」を通知する。

### 3.1 分岐条件

| 条件 | 結果 |
|---|---|
| 受取方法未選択 | 更新せず入力エラー |
| 受取状況が未受取 | 更新可能 |
| 受取状況が受取済 | 更新不可エラー |
| 選択値が現値と同じ | 成功扱いで画面再表示 |

### 3.2 画面遷移

| 遷移元 | 条件 | 遷移先 |
|---|---|---|
| 出資配当金お知らせ画面 | 更新成功 | 出資配当金お知らせ画面 |
| 出資配当金お知らせ画面 | 戻るクリック | トップ画面 |
| 出資配当金お知らせ画面 | ログアウトクリック | ログイン画面 |

### 3.3 トランザクション境界

| 開始 | 終了 | 内容 |
|---|---|---|
| 更新API開始時 | 受取方法更新完了時 | 業務チェックと受取方法更新を単一論理トランザクションで実施 |
| 更新API開始時 | 業務チェックNG時 | ロールバックしてエラー返却 |

## 4. 入力チェック

| 項目 | チェック内容 | エラーコード | 画面表示 |
|---|---|---|---|
| receipt_method | 未選択 | E_101 | 「配当金の受取方法を選択してください」 |
| receipt_method | 定義外値 | E_102 | 「配当金の受取方法が不正です」 |
| notice_id | 未指定 | E_101 | 「対象データが指定されていません」 |
| record_version | 未指定 | E_101 | 「再読込後に再度お試しください」 |

## 5. 例外/エラー処理

### 5.1 入力エラー

| 検知条件 | エラーコード | 表示内容 | 復帰方法 |
|---|---|---|---|
| 受取方法未選択 | E_101 | 「配当金の受取方法を選択してください」 | 選択後に再実行 |
| 定義外値送信 | E_102 | 「配当金の受取方法が不正です」 | 画面再読込 |

### 5.2 業務エラー

| 検知条件 | エラーコード | 表示内容 | 処理 |
|---|---|---|---|
| 受取状況が受取済 | E_202 | 「受取済のため変更できません」 | 最新状態を再表示 |
| 当年対象外 | E_203 | 「当年分のみ変更できます」 | 最新状態を再表示 |
| 登録口座振込を選択したが口座未登録 | E_204 | 「口座登録情報を確認してください」 | 更新せず画面に留まる |
| 同時更新検知 | E_205 | 「他の操作で更新されました。再表示します」 | 画面再読込 |

### 5.3 システムエラー

| 検知条件 | エラーコード | リトライ | 表示内容 | ログ |
|---|---|---|---|---|
| 更新タイムアウト | E_901 | 再試行可 | 「更新に失敗しました。時間をおいて再度お試しください」 | request_id、endpoint、method、user_id、stacktrace |
| DB更新障害 | E_902 | 再試行可 | 「更新に失敗しました」 | 同上 |
| 未処理例外 | E_999 | 再試行可 | 「システムエラーが発生しました」 | 同上 |

### 5.4 セッション切れ/権限不足

| 事象 | エラーコード | 処理 |
|---|---|---|
| セッション切れ | E_003 | ログイン画面へ遷移し、未保存変更は破棄 |
| 権限不足 | E_004 | 403相当画面またはログイン画面へ遷移 |

## 6. データ更新・整合性

| 区分 | 内容 |
|---|---|
| 参照データ | お知らせ情報、配当受取方法情報、口座登録情報 |
| 更新データ | 配当受取方法情報 |
| 更新順序 | 1. セッション確認 2. 対象レコード取得 3. 業務チェック 4. 条件付き更新 |
| 整合性ルール | 更新対象は当年かつ未受取の1レコードのみ。更新後は `updated_at` と `updated_by` を更新する |
| 排他 | 楽観ロックを採用し、`record_version` 一致時のみ更新する |
| 冪等性 | 同一値での再送は成功扱い。二重送信はフロントエンドでボタン非活性化し、サーバー側でも同一値更新を許容する |

## 7. ログ/監査/運用観点

| 区分 | 記録内容 |
|---|---|
| 操作ログ | request_id、機能ID、組合員コード、notice_id、変更前受取方法、変更後受取方法、結果、実行日時 |
| 監査ログ | 金融関連設定変更として、更新者、更新前後値、更新日時を必須記録 |
| 障害解析 | request_id、endpoint、method、stacktrace、user_id |
| 性能観点 | 更新処理は3秒以内を目標。更新後は再取得なしでレスポンス反映可能な項目に限定する |

## 8. 前提

- 受取方法候補は画面イメージより「出資振替」「登録口座振込」「現金受取」の3値とする。
- 口座未登録時に「登録口座振込」を選択できるかは業務ルール未定のため、本設計では更新不可とした。

## 9. 要確認事項

- 受取方法変更の締切日、締切後の画面制御。
- 現金受取選択時のバーコード発行との連動条件。
