# 処理設計書

**ファイルパス**: `docs/ED/product/TOP_001_process-design.md`

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | TOP_001 |
| 機能名 | トップ画面表示 |
| 目的/ゴール | ログイン済み利用者に対して、出資配当金のお知らせ一覧とマイページ導線を表示する。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | ログイン成功後の画面遷移、トップ画面再表示、ブラウザ再読込 |
| 入力 | セッション情報、表示対象年度条件（内部）、お知らせ選択操作、マイページリンク操作 |
| 出力 | ヘッダ情報、お知らせ一覧、未読相当の New 表示、マイページ導線 |
| 前提条件 | ログイン済みであること。表示対象利用者に紐づくお知らせデータが参照可能であること。 |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| session_id | string | Y | 有効セッションであること | セッション保持値 |
| user_code | string | Y | セッション内の組合員コード | セッション保持値 |
| notice_filter_year | number | N | 指定がない場合は公開中データ全件 | なし |

### 2.2 出力項目

| 項目名 | 型 | 内容 |
|---|---|---|
| header_user_code | string | ヘッダ表示用の組合員コード |
| header_login_name | string | ヘッダ表示用の利用者名 |
| notice_list | array | お知らせ一覧 |
| notice_list[].notice_id | string | お知らせ識別子 |
| notice_list[].fiscal_year | number | 対象年度 |
| notice_list[].title | string | 画面リンク表示名 |
| notice_list[].is_new | boolean | New 表示判定 |
| mypage_link | string | マイページ遷移先 |

### 2.3 画面状態

| 状態名 | 内容 |
|---|---|
| loading | 初期表示/API取得中 |
| success | 一覧表示完了 |
| empty | 対象データなし |
| error | API取得失敗 |

## 3. 処理フロー（正常系）

1. ログイン成功後、トップ画面へ遷移する。
2. フロントエンドはヘッダ領域とコンテンツ領域を `loading` 状態で表示する。
3. トップ画面表示APIはセッションを検証し、利用者基本情報を取得する。
4. 利用者に紐づく公開中のお知らせ一覧を年度降順で取得する。
5. 直近未確認または最新公開のお知らせに `is_new=true` を付与する。
6. 取得結果をレスポンスとして返却する。
7. フロントエンドはお知らせ一覧をリンク形式で表示し、マイページリンクを表示する。
8. 利用者がお知らせを選択した場合は出資配当金お知らせ画面へ遷移する。
9. 利用者がマイページを選択した場合はマイページ画面へ遷移する。

### 3.1 分岐条件

| 条件 | 結果 |
|---|---|
| お知らせが1件以上ある | 一覧を表示 |
| お知らせが0件 | 空状態メッセージを表示 |
| セッション無効 | ログイン画面へ遷移 |

### 3.2 画面遷移

| 遷移元 | 条件 | 遷移先 |
|---|---|---|
| ログイン画面 | ログイン成功 | トップ画面 |
| トップ画面 | お知らせ行クリック | 出資配当金お知らせ画面 |
| トップ画面 | マイページリンククリック | マイページ画面 |
| トップ画面 | ログアウトクリック | ログイン画面 |

### 3.3 トランザクション境界

| 開始 | 終了 | 内容 |
|---|---|---|
| 表示API開始時 | レスポンス返却時 | 参照専用処理のため更新トランザクションなし |

## 4. 入力チェック

| 項目 | チェック内容 | エラーコード | 画面表示 |
|---|---|---|---|
| session_id | 有効性確認 | E_003 | ログイン画面へ遷移 |
| notice_filter_year | 数値形式 | E_102 | 「表示条件が不正です」 |

## 5. 例外/エラー処理

### 5.1 入力エラー

| 検知条件 | エラーコード | 表示内容 | 復帰方法 |
|---|---|---|---|
| 不正な表示条件 | E_102 | 「表示条件が不正です」 | 既定条件で再表示 |

### 5.2 業務エラー

| 検知条件 | エラーコード | 表示内容 | 処理 |
|---|---|---|---|
| お知らせ未登録 | なし | 「現在表示できるお知らせはありません」 | 空状態を表示 |
| 利用者情報不整合 | E_201 | 「利用者情報を確認できませんでした」 | ログイン画面へ戻す |

### 5.3 システムエラー

| 検知条件 | エラーコード | リトライ | 表示内容 | ログ |
|---|---|---|---|---|
| DB取得タイムアウト | E_901 | 再試行ボタン表示可 | 「情報の取得に失敗しました」 | request_id、endpoint、method、user_id、stacktrace |
| 未処理例外 | E_999 | 再試行可 | 「システムエラーが発生しました」 | 同上 |

### 5.4 セッション切れ/権限不足

| 事象 | エラーコード | 処理 |
|---|---|---|
| セッション切れ | E_003 | ログイン画面へ遷移し「再度ログインしてください」を表示 |
| 権限不足 | E_004 | 403相当画面またはログイン画面へ遷移 |

## 6. データ更新・整合性

| 区分 | 内容 |
|---|---|
| 参照データ | 組合員基本情報、お知らせ情報 |
| 更新データ | なし。既読管理を実装する場合は別機能で管理 |
| 更新順序 | 1. セッション確認 2. ヘッダ情報取得 3. お知らせ一覧取得 |
| 整合性ルール | ヘッダ情報とお知らせ一覧は同一利用者に紐づくデータのみ返却する |
| 排他 | 参照専用のため排他制御なし |
| 冪等性 | 同一条件の再表示は同一結果を返す |

## 7. ログ/監査/運用観点

| 区分 | 記録内容 |
|---|---|
| 操作ログ | request_id、機能ID、組合員コード、結果、表示件数、実行日時 |
| 監査ログ | 重要データ更新なしのため操作ログで代替 |
| 障害解析 | request_id、endpoint、method、stacktrace、user_id |
| 性能観点 | お知らせ一覧は最大50件まで表示、超過時はページングまたは年度絞込を要検討 |

## 8. 前提

- 画面イメージからトップ画面の主表示は「お知らせ一覧」と「マイページ導線」であり、詳細な出資配当情報自体は次画面で確認する前提とする。
- New 表示は最新年度または未確認フラグで判定する前提とし、厳密な既読管理方式は要確認とする。

## 9. 要確認事項

- お知らせ一覧の表示上限とページング有無。
- New 表示の判定条件を「最新1件固定」とするか、「未読管理」とするか。
