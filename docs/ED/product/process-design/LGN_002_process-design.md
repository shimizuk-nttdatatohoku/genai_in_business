# 処理設計書

**ファイルパス**: `docs/ED/product/LGN_002_process-design.md`

## 1. 機能概要

| 項目 | 内容 |
|---|---|
| 機能ID | LGN_002 |
| 機能名 | ログアウト |
| 目的/ゴール | 利用中セッションを安全に破棄し、未ログイン状態へ戻す。 |
| 利用者 | 組合員 |
| 画面/操作トリガー | SCR-002、SCR-003、SCR-004 のヘッダに配置されたログアウトボタンのクリック |
| 入力 | セッションID、CSRF対策トークン |
| 出力 | ログアウト結果、ログイン画面への遷移 |
| 前提条件 | ログイン済みで有効なセッションを保持していること。 |

## 2. 入出力データ定義

### 2.1 入力項目

| 項目名 | 型 | 必須 | 制約 | 初期値 |
|---|---|---|---|---|
| session_id | string | Y | サーバー発行済みの有効セッションID | セッション保持値 |
| csrf_token | string | Y | サーバーが発行したトークンと一致すること | 画面保持値 |
| request_id | string | Y | サーバー側採番 | なし |

### 2.2 出力項目

| 項目名 | 型 | 内容 |
|---|---|---|
| logout_result | boolean | ログアウト成功時 `true` |
| redirect_path | string | ログイン画面 |
| message | string | 必要に応じた画面メッセージ |

### 2.3 画面状態

| 状態名 | 内容 |
|---|---|
| idle | 通常表示 |
| processing | ログアウトAPI呼出中。ボタン非活性 |
| completed | セッション破棄完了。ログイン画面へ遷移 |

## 3. 処理フロー（正常系）

1. 利用者が各画面のログアウトボタンをクリックする。
2. フロントエンドはログアウトボタンを非活性にし、`processing` 状態にする。
3. ログアウトAPIはセッションIDとCSRF対策トークンを検証する。
4. 有効なセッションであることを確認し、セッション情報を無効化する。
5. セッションクッキー、クライアント保持の利用者情報を削除する。
6. ログイン画面へ遷移する。

### 3.1 分岐条件

| 条件 | 結果 |
|---|---|
| セッション有効 | 正常に破棄してログイン画面へ遷移 |
| セッション既失効 | 正常終了扱いでログイン画面へ遷移 |

### 3.2 画面遷移

| 遷移元 | 条件 | 遷移先 |
|---|---|---|
| トップ画面 | ログアウト成功 | ログイン画面 |
| 出資配当金お知らせ画面 | ログアウト成功 | ログイン画面 |
| マイページ画面 | ログアウト成功 | ログイン画面 |

### 3.3 トランザクション境界

| 開始 | 終了 | 内容 |
|---|---|---|
| ログアウトAPI開始時 | セッション無効化完了時 | セッション破棄を単一更新処理として実施 |

## 4. 入力チェック

| 項目 | チェック内容 | エラーコード | 画面表示 |
|---|---|---|---|
| session_id | 未設定 | E_003 | 画面メッセージは表示せずログイン画面へ遷移 |
| csrf_token | 不一致 | E_004 | 「不正な操作が検知されました」 |

## 5. 例外/エラー処理

### 5.1 入力エラー

| 検知条件 | エラーコード | 表示内容 | 復帰方法 |
|---|---|---|---|
| CSRF対策トークン不正 | E_004 | 「不正な操作が検知されました」 | ログイン画面へ遷移 |

### 5.2 業務エラー

| 検知条件 | エラーコード | 表示内容 | 処理 |
|---|---|---|---|
| セッション既失効 | E_003 | 表示なし | 正常終了扱いでログイン画面へ遷移 |

### 5.3 システムエラー

| 検知条件 | エラーコード | リトライ | 表示内容 | ログ |
|---|---|---|---|---|
| セッションストア更新障害 | E_902 | 不要。クライアント側は強制的にログイン画面へ遷移 | 「ログアウト処理中にエラーが発生しました」 | request_id、endpoint、method、user_id、stacktrace |
| 未処理例外 | E_999 | 不要。同上 | 「システムエラーが発生しました」 | 同上 |

### 5.4 セッション切れ/権限不足

| 事象 | エラーコード | 処理 |
|---|---|---|
| セッション切れ | E_003 | ログイン画面へ遷移 |
| 権限不足 | E_004 | 403相当画面またはログイン画面へ遷移 |

## 6. データ更新・整合性

| 区分 | 内容 |
|---|---|
| 参照データ | セッション情報 |
| 更新データ | セッション情報 |
| 更新順序 | 1. セッション存在確認 2. セッション無効化 3. クライアント側情報削除 |
| 整合性ルール | セッション無効化後は認証必須画面へ再入場できないこと |
| 排他 | セッション無効化は同一セッションに対する条件付き更新で実施 |
| 冪等性 | 既に無効なセッションに対する再実行は成功扱いとする |

## 7. ログ/監査/運用観点

| 区分 | 記録内容 |
|---|---|
| 操作ログ | request_id、機能ID、組合員コード、セッションID、結果、実行日時 |
| 監査ログ | ログアウト実行有無、失効対象セッションID |
| 障害解析 | request_id、endpoint、method、stacktrace、user_id |
| 性能観点 | 応答は1秒以内を目標とし、画面遷移を優先する |

## 8. 前提

- ログアウトAPIのURLは `/api/v1/logout` を想定する。
- セッション破棄失敗時でもクライアント側は認証情報を破棄し、再利用を防止する。

## 9. 要確認事項

- セッション無効化をサーバー側ストア管理とするか、署名付きトークン失効リスト管理とするか。
- ログアウト前の確認ダイアログ有無。
