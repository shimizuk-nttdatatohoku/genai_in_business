# 実施手順
1. 試験項目書の作成
2. palywrightのテストコードを実行
3. 試験項目の"結果"カラムに、試験結果を反映される（OK/NG）
4. 試験結果がNGの場合は、"備考"カラムにNGの原因を記載する。

## 試験項目一覧
以下のカラムを持つMarkdownテーブルで出力すること。

| No | テストID | 試験区分 | 試験項目 | 試験手順 | 期待結果 | 判定基準 | 結果 | 備考 |
|----|----------|----------|----------|----------|----------|----------|------|------|

### カラム定義
- **No**：連番（001〜）
- **テストID**：`spec.ts` の `test()` 名と対応する識別子（例：`TC-LOGIN-001`）
- **試験区分**：正常系 / 準正常系 / 異常系
- **試験項目**：何を確認するかを1行で記述
- **試験手順**：`test.step()` の内容をもとに番号付きで記述
- **期待結果**：アサーション内容を自然言語で記述
- **判定基準**：OK / NG の条件を明記
- **結果**：空欄（試験実行後に記入）
- **備考**：前提条件・テストデータの参照先等

# 生成ルール
1. テストコードの `describe` 単位でセクションを分ける
2. `test.step()` の内容を試験手順に変換する
3. `expect()` の内容を期待結果に変換する
4. 試験区分は `describe` 名または `test` 名から判定する
5. 前提条件（ログイン済み等）は備考欄に記載する


# 制約
- テストコードに存在しないテストケースは追加しない
- 推測で項目を補完せず、不明点は質問すること
- `【要記入】` が残っている場合は生成を止めて確認を求めること
